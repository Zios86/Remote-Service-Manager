# Архитектурные решения

## ADR-001: PowerShell 5.1 и WPF как текущая платформа

**Статус:** принято.

**Причина:** программа должна запускаться на корпоративных Windows 10/11 без установки среды выполнения и без прав администратора.

**Следствие:** сохраняем совместимость 5.1 и BOM; сложную многопоточность не добавляем без необходимости.

## ADR-002: Kerberos-only для Windows

**Статус:** принято в 2.2.0.

**Причина:** текущая доменная УЗ должна использоваться без передачи пароля, а сервер должен быть аутентифицирован.

**Следствие:** Windows-цель задаётся DNS-именем; IP и скрытый fallback на NTLM не поддерживаются.

## ADR-003: OpenSSH вместо агента на Linux

**Статус:** принято.

**Причина:** не устанавливать собственное ПО на ALT Linux и использовать штатный защищённый транспорт.

**Следствие:** требуется SSH, systemd, ключ/agent и заранее проверенный host key; каждая операция создаёт отдельный процесс ssh.

## ADR-004: systemd mask соответствует Disabled

**Статус:** принято.

**Причина:** `disable` запрещает автозапуск, но не ручной запуск. Наиболее близкий аналог Windows Disabled — `mask`.

**Следствие:** Automatic = enable, Manual = disable, Disabled = mask; запуск masked-unit требует явного unmask.

## ADR-005: Mutable data вне каталога приложения

**Статус:** принято в 2.1.0.

**Причина:** запуск возможен из read-only или сетевой папки, а данные разных специалистов не должны смешиваться.

**Следствие:** снимки и аудит хранятся в `%LOCALAPPDATA%\RemoteServiceManager`.

## ADR-006: Один общий файл правил для ИИ

**Статус:** принято.

**Причина:** дублирующиеся инструкции расходятся со временем.

**Следствие:** общие правила находятся в `AGENTS.md`; `CLAUDE.md` импортирует его и содержит только Claude-специфичные заметки.
