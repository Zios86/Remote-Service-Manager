# Безопасность

## Защищаемые активы

- доступ специалиста к удалённым АРМ;
- работоспособность WinRM/SSH, сети, входа и системных служб;
- доменные и SSH-учётные данные;
- целостность команд, журналов и снимков;
- защита от завершения чужого процесса после повторного использования PID.

## Windows

- Использовать Kerberos и DNS-имя цели.
- Не выполнять автоматический fallback на NTLM.
- Не изменять `TrustedHosts`.
- Не включать Basic/CredSSP без отдельного согласованного требования и анализа риска.
- Не отключать проверку сертификата при будущем добавлении WinRM HTTPS.

## Linux

- `BatchMode=yes` и отсутствие интерактивного ввода паролей.
- `StrictHostKeyChecking=yes`; первое доверие устанавливает администратор после сверки отпечатка.
- Agent Forwarding, X11, PTY и port forwarding выключены.
- При явном ключе используется `IdentitiesOnly=yes`.
- Административные команды выполняются только через root или разрешённый `sudo -n`.
- Имена units проходят allowlist-валидацию; удалённая команда передаётся в base64.

## Опасные операции

Перед остановкой, перезапуском, отключением службы или завершением процесса обязательны:

1. явный выбор флажком;
2. проверка встроенного списка защиты;
3. подтверждение пользователя;
4. снимок состояния, если применимо;
5. повторная проверка результата;
6. запись результата и ошибки в аудит.

## Файлы и журналы

- Runtime-данные сохраняются в `%LOCALAPPDATA%\RemoteServiceManager`.
- Строки CSV, начинающиеся с формульных символов Excel, экранируются.
- BAT сверяет SHA-256 исполняемых PS1.
- Конфигурационный JSON не является доверенной границей для критической защиты: основной список критических Windows-служб остаётся в коде.

## Остаточные риски

- SHA-256 внутри того же каталога защищает от случайной порчи, но не от злоумышленника, способного заменить BAT и PS1 одновременно.
- PowerShell `ExecutionPolicy Bypass` используется для портативного запуска и не является механизмом безопасности.
- Для промышленного развёртывания нужны Authenticode, WDAC/AppLocker, контролируемый канал распространения и централизованный аудит.
- Права sudo определяются администраторами Linux; программа не редактирует sudoers.
