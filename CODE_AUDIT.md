# Аудит Remote Service Manager

Версия после исправлений аудита: 2.2.0

## Архитектура 2.2

- Windows-компьютеры управляются через постоянную WinRM/PSSession.
- Linux-компьютеры управляются через штатный OpenSSH-клиент Windows.
- Linux-команды принимают только проверенные имена systemd-unit и числовые PID.
- Пароли не передаются в аргументах и не сохраняются; SSH работает в BatchMode.
- Текущая доменная УЗ определяется локально, а SSH-имя передаётся через -l;
  пароль и токен интерактивного входа Windows не используются.
- Устаревший список очищается до подключения и при любой ошибке загрузки.
- PID сверяется с именем и временем запуска непосредственно перед завершением.
- Завершение процессов журналируется отдельно по каждому результату.
- WinRM/SSH имеют контролируемое ожидание и тайм-аут.
- SSH host key должен быть заранее подтверждён в known_hosts.
- BAT проверяет SHA-256 двух исполняемых PowerShell-файлов до запуска.
- Номер версии интерфейса и журнала читается из единого VERSION.txt.
- Повышение прав выполняется только через root или `sudo -n`.
- Снимки Windows и Linux разделены по платформе и компьютеру.
- Критические SSH, D-Bus, logind и сетевые службы защищены от остановки.
- Windows-транспорт явно закреплён за Kerberos; скрытого перехода на NTLM нет.
- IP-адреса Windows отклоняются, поскольку Kerberos требует DNS-имя/SPN.
- Удалённый профиль пользователя не загружается в служебной WinRM-сессии.
- SSH запрещает PTY, agent forwarding, X11 и перенаправление портов.
- Конфигурация проверяется по версии схемы и обязательным разделам.
- Строки CSV нейтрализуются перед экспортом и не запускаются как формулы Excel.

## Исправлено

- Удалён неиспользуемый путь `Disable` из обработчика запуска/остановки. Перевод
  в `Disabled` выполняется только через единый механизм изменения типа запуска.
- Удалено смешивание WPF и `System.Windows.Forms.Application.DoEvents`, которое
  допускало повторный вход в обработчики во время незавершённой операции.
- Кнопки итогового окна больше не зависят от хрупких локальных замыканий.
- Откат выбирает последний снимок только для подключённого компьютера.
- Неизвестный тип запуска в снимке теперь вызывает ошибку вместо молчаливой
  замены на `Manual`.
- Журнал Service Control Manager запрашивается один раз за диагностику, а не
  повторно для каждой выбранной службы.
- Упрощена классификация служб по маскам.
- Упрощена настройка `DelayedAutoStart`; устаревший флаг очищается при выборе
  любого другого типа запуска.
- Ожидание результата команды использует типизированные состояния Windows.
- Чекбокс категории синхронизируется с индивидуальным выбором служб и показывает
  промежуточное состояние, если выбрана только часть группы.
- Удалено скрытое вычисляемое поле `Protection`; защита продолжает проверяться
  непосредственно перед опасной операцией.

## Проверено статически

- XML/XAML интерфейса;
- наличие всех именованных элементов управления;
- JSON конфигурации групп и защищённых служб;
- соответствие версии файлов;
- наличие обработчиков основных операций;
- UTF-8 BOM для Windows PowerShell 5.1;
- целостность ZIP-архива.
- маршрутизация операций между Windows и Linux;
- наличие Linux-функций служб, процессов, диагностики и отката;
- проверка допустимых имён systemd-unit и PID;
- UTF-8 BOM для основного скрипта и Linux-модуля.
- DNS/IP-проверка цели Windows и явный выбор Kerberos;
- параметры безопасного запуска OpenSSH;
- схема и обязательные поля service-groups.json.
- нейтрализация CSV-формул и безопасное формирование имён отчётов.

Запуск выполняется через ASCII-файл `Запустить.bat`. Он использует `pushd`,
поэтому работает как из локальной папки, так и из сетевого UNC-пути.

## Ограничение проверки

Windows-команды требуют тестового компьютера с WinRM. Linux-команды требуют
тестового компьютера с SSH, systemd и настроенными правами root/sudo. В среде
сборки нет доступа к корпоративным АРМ и ALT Linux с запущенным systemd, поэтому
фактическое изменение удалённых служб необходимо проверить на тестовом АРМ.

SHA-256 в BAT обнаруживает изменение файлов комплекта, но не заменяет
корпоративную Authenticode-подпись: пользователь, способный заменить BAT, может
заменить и контрольные суммы. Для промышленного распространения рекомендуется
подписать PS1 корпоративным сертификатом и применять разрешающие политики WDAC.
