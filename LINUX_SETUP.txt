ПОДГОТОВКА LINUX ДЛЯ REMOTE SERVICE MANAGER 2.2.0

Программа запускается на Windows и подключается к Linux по SSH.
Она рассчитана на Linux с systemd, включая ALT Workstation K.

1. На Linux администратор должен проверить:

   systemctl --version
   systemctl status sshd
   command -v systemctl
   command -v sudo
   command -v base64
   command -v timeout
   command -v ps
   command -v awk
   command -v getconf

2. На Windows проверьте наличие клиента:

   ssh -V

   Если команда не найдена, установите дополнительный компонент Windows
   «Клиент OpenSSH».

3. Создайте отдельный SSH-ключ на Windows:

   ssh-keygen -t ed25519

   Открытый ключ нужно добавить на Linux в файл пользователя:

   ~/.ssh/authorized_keys

   Закрытый ключ остаётся только на Windows. Не отправляйте его коллегам и не
   помещайте в общую сетевую папку.

   Для режима «Текущая УЗ» открытый ключ необходимо добавить именно доменному
   пользователю, которого ALT Linux определяет командой:

   id 'пользователь@домен'

   Имя текущей учётной записи программа получает автоматически из Windows.
   Если принятый в организации формат отличается, снимите флажок «Текущая УЗ»
   и укажите DOMAIN\user либо другое разрешённое SSH-имя вручную.

4. Проверьте вход из Windows:

   ssh -p 22 -i C:\ПУТЬ\К\КЛЮЧУ -l пользователь@домен имя_или_ip "systemctl --version"

   При первом входе сравните отпечаток ключа узла с данными администратора и
   подтвердите его. Remote Service Manager использует строгую проверку
   known_hosts и сам неизвестные ключи не принимает.

   Рабочие команды запускаются без псевдотерминала, SSH Agent Forwarding, X11
   и перенаправления портов. Если ключ выбран в интерфейсе, используется только
   он; лишние ключи из профиля и агента не перебираются.

5. Для изменения служб Linux-администратор должен предоставить отдельной
   учётной записи минимально необходимые права sudo без запроса пароля на:

   systemctl start / stop / restart / enable / disable / mask / unmask
   kill -TERM

   Точный путь к systemctl и правила sudo должен определить администратор Linux
   командой `command -v systemctl`. Программа намеренно не изменяет sudoers.

6. Проверьте права из Windows:

   ssh -p 22 -i C:\ПУТЬ\К\КЛЮЧУ -l пользователь@домен имя_или_ip "sudo -n systemctl status sshd.service"

   Запрос пароля или сообщение «a password is required» означает, что права
   для работы программы ещё не настроены.

В корпоративной сети сначала проверьте VPN, DNS, доступность TCP-порта SSH и
правила межсетевого экрана. Пароли и одноразовые коды в программу не вводятся.
