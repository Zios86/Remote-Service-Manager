УДАЛЁННОЕ УПРАВЛЕНИЕ СЛУЖБАМИ

Версия 2.2.1

1. Запустите файл «Запустить.bat».
2. Выберите тип удалённой системы: Windows или Linux.
3. Для Windows введите DNS-имя компьютера; для Linux — имя или IP. Для Windows
   при необходимости включите «Другие учётные данные»; для Linux укажите SSH.
4. Нажмите «Подключиться».
5. Отметьте нужные службы флажками.
6. Нажмите «Запустить», «Остановить» или «Перезапустить». Для изменения типа
   запуска выберите вариант в списке и нажмите «Изменить тип запуска».
7. Подтвердите операцию.

Файл «Запустить.bat» сразу открывает программу. Он поддерживает запуск с
локального диска, подключённого сетевого диска и из сетевой UNC-папки.

Перед запуском BAT проверяет SHA-256 основного PowerShell-файла и Linux-модуля.
Если файлы изменены или повреждены, запуск блокируется. После самостоятельного
редактирования кода контрольные суммы в BAT необходимо обновить. Настройка
групп в service-groups.json остаётся доступной без пересборки.

Службы автоматически объединяются в смысловые группы: EAS4 и RussianPost EAS,
MARS, базы данных, безопасность и криптография, печать, мониторинг и диагностика,
администрирование АРМ, сеть, обновления, прочие системные службы. Группу можно
выбрать в фильтре, а кнопка «Выбрать показанные» отметит все службы этой группы.
Готовые фильтры отображаются всегда, даже если на текущем компьютере в группе
не найдено ни одной службы. Кнопка «Мониторинг процессов» открывает вкладку
процессов и сразу включает обновление показателей.

БЕЗОПАСНОЕ ПОДКЛЮЧЕНИЕ К WINDOWS

Программа использует WinRM/WS-Man с Kerberos. Указывайте имя компьютера, например
R78-191036-W01, а не его IP-адрес. Под текущей доменной учётной записью пароль
не запрашивается и не передаётся программе. Если выбраны другие учётные данные,
они используются только объектом PSCredential для Kerberos-сессии.

Программа намеренно не выполняет автоматический переход на NTLM и не добавляет
компьютеры в TrustedHosts. Это защищает от подключения к подменённому серверу.

ПОДКЛЮЧЕНИЕ К LINUX

1. Выберите «Linux» в поле «Система».
2. Укажите имя или IP Linux-компьютера и порт (обычно 22).
3. Оставьте «Текущая УЗ» включённой, чтобы использовать имя доменной учётной
   записи, под которой запущена программа. Если на Linux требуется другое имя,
   снимите флажок и укажите SSH-пользователя вручную.
4. Выберите закрытый SSH-ключ либо оставьте поле пустым, если ключ уже доступен
   через ssh-agent или стандартный профиль OpenSSH.
5. Нажмите «Подключиться».

Перед первым подключением один раз подтвердите ключ Linux-компьютера в обычной
консоли Windows:

ssh -p 22 -l пользователь@домен ИМЯ_ИЛИ_IP exit

Сравните отпечаток с данными администратора Linux и ответьте yes. Программа не
принимает неизвестные ключи автоматически и блокирует изменившийся ключ узла.

На Windows должен быть установлен компонент «Клиент OpenSSH». Программа не
сохраняет и не передаёт пароль. Интерактивный ввод пароля отключён. Режим
«Текущая УЗ» использует имя пользователя Windows, но SSH-аутентификация всё
равно выполняется ключом или ssh-agent. ALT Linux должен распознавать эту
доменную учётную запись через настроенную в организации доменную интеграцию.

Для просмотра служб и процессов достаточно обычного SSH-доступа. Для запуска,
остановки, enable/disable/mask и завершения чужих процессов пользователь должен
быть root либо иметь разрешение sudo без интерактивного запроса пароля. Если
прав недостаточно, в журнале появится исходная ошибка sudo/systemctl.

Linux-часть рассчитана на систему с systemd, включая ALT Workstation K.
Перед внедрением проверьте корпоративные правила SSH, VPN, межсетевой экран и
политику sudo. Не помещайте пароль или секреты в поля программы и журналы.

ОГРАНИЧЕНИЯ LINUX

- «Automatic (Delayed)» отсутствует, поскольку прямого аналога Windows в
  systemd нет;
- первое измерение CPU Linux равно 0; со второго обновления значение считается
  по разнице накопленного процессорного времени;
- неподдерживаемые в Linux колонки диска и дескрипторов скрыты;
- для изменения служб используются только systemctl, sudo и SSH.

Файл service-groups.json можно редактировать в Блокноте. В нём разрешается
добавлять маски служб, например "eas4-*" или "RussianPostEAS*". После изменения
файла программу необходимо перезапустить.

Если выбранная служба имеет тип запуска Disabled, программа отдельно предложит
изменить тип запуска на Manual. Без этого Windows не позволит запустить службу.

Тип запуска Disabled запрещает автоматический и ручной запуск выбранной службы.
Уже работающая служба при этом продолжает работать до отдельной остановки или
перезагрузки компьютера. Это стандартное поведение Windows.

Общие требования:
- Windows PowerShell 5.1 на компьютере специалиста;
- сетевой доступ к удалённому компьютеру.

Для Windows-цели:
- PowerShell Remoting (WinRM);
- учётная запись с правами на управление службами.

Для Linux-цели:
- OpenSSH Client на Windows и SSH-сервер на Linux;
- systemd и утилиты systemctl, ps, journalctl, base64 и timeout;
- SSH-ключ или настроенный ssh-agent;
- root либо разрешённые команды sudo без запроса пароля.

Проверка подключения:
Test-WSMan ИМЯ-КОМПЬЮТЕРА

Включение PowerShell Remoting на целевом компьютере от администратора:
Enable-PSRemoting -Force

Важно: остановка системных служб может нарушить работу удалённого компьютера.
Перед выполнением программа показывает список выбранных служб и запрашивает подтверждение.
Для запуска, остановки и изменения типа запуска необходимы соответствующие права
на удалённом компьютере.

ВКЛАДКА «ПРОЦЕССЫ»

- показывает загрузку CPU, память, дисковую активность, PID, потоки и дескрипторы;
- обновляет показатели каждые 2, 5, 10 или 30 секунд;
- позволяет искать процесс по имени или PID;
- позволяет завершать несколько отмеченных процессов;
- защищает критические системные процессы и процесс удалённого подключения;
- повторно проверяет имя и время запуска выбранного PID;
- перед завершением всегда запрашивает подтверждение.

CPU отображается как доля общей мощности всех логических процессоров, то есть
значение нормализовано аналогично Диспетчеру задач Windows.
